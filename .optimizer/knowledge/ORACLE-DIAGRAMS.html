5. API Architecture

sequenceDiagram
    participant U as User Browser
    participant F as Frontend (Next.js)
    participant A as API Route (/api/oracle)
    participant C as Cache (60s TTL)
    participant R as RPC Provider
    participant P as PoolManager

    U->>F: GET /oracle
    F->>A: fetch('/api/oracle')
    A->>C: Check Cache
    
    alt Cache HIT
        C-->>A: Return cached data
    else Cache MISS
        A->>R: getLogs(SWAP_TOPIC)
        R->>P: eth_getLogs
        P-->>R: Event logs
        R-->>A: Raw logs
        A->>A: Parse & Analyze
        A->>C: Store result
    end
    
    A-->>F: JSON Response
    F-->>U: Render Terminal UI
    
    Note over U,P: Auto-refresh every 60s

8. Data Flow Summary

Stage Input Process Output
1. Collection Ethereum RPC eth_getLogs(SWAP_TOPIC) Raw event logs
2. Parsing Event logs Decode topics[1]=poolId, topics[2]=sender, data=amounts Structured swap objects
3. Filtering Swaps Remove known contracts (V4 Settled, Uniswap Router) User swaps only
4. Classification Swaps Determine buy/sell from amount0 direction Labeled swaps
5. Grouping Labeled swaps Group by poolId, sender, block Pool & trader stats
6. MEV Detection Grouped data Pattern matching: sandwich, front-run, arbitrage Attack list + bot classification
7. Intelligence MEV results Cross-pool analysis, volume estimation Recommendations
8. API Response Analysis JSON serialization + cache Structured JSON
9. Display JSON React component rendering Terminal-style UI
